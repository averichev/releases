# Публикация релизов и манифесты

## Жизненный цикл

Релиз создаётся как `draft`. Администратор загружает исполняемые файлы, установщики, архивы и updater-пакеты для нужных платформ, проверяет готовность и публикует. Обязательного списка платформ нет. Несколько форматов установщика одной платформы допустимы. Installer и updater могут иметь одинаковые target/format; updater допускается один на target.

Проверка готовности проверяет активность приложения, наличие файлов, совместимость updater, размер и SHA-256 через ArtifactStorage. Ответ содержит `state=ready|warnings|errors`, массивы проблем с `code,artifact_id,message`. Отсутствующая подпись updater даёт предупреждение: такой файл доступен по прямой ссылке, но не участвует в обновлениях.

Публикация заново проверяет файлы без длительного удержания write lock. Затем `BEGIN IMMEDIATE` повторно проверяет действующую session/admin, статус приложения, revision релиза и точное совпадение состава/метаданных файлов. Статус, дата первой публикации, revision и факт публикации фиксируются атомарно. Конкурентное изменение возвращает `409 publication_conflict`. Сбой записи истории откатывает публикацию. Повтор завершённого запроса не создаёт событие повторно.

Опубликованная версия, описание, существующие файлы, роли и подписи неизменяемы; удаление запрещено сервисами и SQLite. Можно добавить новый файл с прежними проверками активного приложения, живой сессии и уникальности. Для добавляемого опубликованного updater обязательна корректная по структуре `.sig` в том же запросе. Добавление увеличивает revision, сохраняя published_at, updated_at и историю публикации. Файловая система и SQLite не считаются одной транзакцией: сохраняются временные объекты, атомарное перемещение, компенсация и startup reconciliation.

## Определение актуальных версий

`/{slug}/latest/{target}` выбирает максимальный опубликованный SemVer с установщиком нужной платформы. Черновики и prerelease исключены. Build metadata сохраняется, но не меняет приоритет. При нескольких форматах выбранной версии ответ `409 ambiguous_artifact` требует `?format=exe` или другой формат. Явный формат выбирает максимальную версию, содержащую именно этот формат. Загрузка дополнительных форматов разрешена.

Например: опубликован `0.5.0` с macOS DMG, затем в ту же версию добавлен Windows EXE. После публикации `0.6.0` только с DMG macOS получает `0.6.0`, Windows остаётся на `0.5.0`. `/{slug}/latest` без query возвращает `307` на страницу выбора установщика `/{slug}`. Redirect имеет `Cache-Control: no-store`.

Прямые ссылки на опубликованные версии и UUID артефактов сохраняются, включая prerelease. Без параметра type/purpose `latest` сохраняет выбор installer. Для executable и archive используются `?type=executable` и `?type=archive`; type — alias прежнего purpose. Пример: `/{slug}/latest?target=linux-x86_64&type=executable`. При нескольких подходящих файлах возвращается 409 с требованием уточнить параметры. Явный type=updater — скачивание файла; Tauri обновления используют свой resolver.

## Универсальный манифест

`GET /{slug}/manifest.json?limit=20`, limit 1–100. `schema_version=2`:

```json
{
  "schema_version": 2,
  "app": "product",
  "latest_by_target": {
    "windows-x86_64": {"version":"0.5.0","published_at":"2026-11-20T10:00:00Z","notes":"","artifacts":[]},
    "darwin-aarch64": {"version":"0.6.0","published_at":"2026-11-20T11:00:00Z","notes":"","artifacts":[]}
  },
  "releases": []
}
```

В примере списки файлов сокращены. `latest_by_target` содержит установщики всех форматов актуальной версии каждой платформы, независимо от limit истории. Дополнительный `latest_by_type` содержит executable/installer/archive → target → Release DTO с независимыми версиями по типам; прежний latest_by_target сохраняется. `releases` — опубликованная история по SemVer убыванию, включая prerelease. Artifact содержит `id,target,format,purpose,size_bytes,sha256,download_url`; постоянный URL указывает на конкретный UUID. Подписи и storage keys не раскрываются. У private/archived административного preview поле download_url отсутствует. Пустая история возвращает 200, `latest_by_target={}`, `releases=[]`.

Манифест и публичный каталог читают метаданные из одного SQLite snapshot. Каждому возвращаемому файлу проверяются ключ, regular file, отсутствие symlink и размер. Полный SHA-256 выполняется при хранении/публикации и явной проверке, не на скачиваниях. ETag — слабый SHA-256 JSON; If-None-Match даёт 304 после проверок доступа и файлов. Cache-Control: public, no-cache. CORS разрешён для публичного чтения. Private/archived/неизвестный slug — 404; неизвестные query — 400.

В панели доступны JSON preview, копирование JSON и URL, история фактов публикации, готовые ссылки платформ и диагностика HEAD. Оператор читает историю, распространение и Tauri preview; публикация и preview полного административного манифеста требуют admin.

## Tauri Updater

`GET /api/v1/updates/tauri/{slug}/{target}/{arch}/{currentVersion}` выбирает максимальную опубликованную версию с совместимым подписанным updater для платформы. Более новые installer-only и неподписанные релизы не скрывают предыдущий рабочий updater. Prerelease исключены. При одинаковой или большей версии клиента — 204; downgrade отсутствует.

Windows: updater EXE/MSI; Linux: AppImage; macOS: app.tar.gz. Для macOS при отсутствии точной архитектуры в релизе разрешён `darwin-universal`; некорректный точный пакет не подменяется Universal из того же релиза. Проверка `.sig` на сервере проверяет envelope, криптографическую подпись проверяет Tauri-клиент своим ключом. Полное руководство: [Tauri](integrations/tauri.md).

Переход существующей базы: [политика миграции 0009](migration-0009.md).
