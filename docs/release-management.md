# Публикация релизов и манифесты — этапы 5–6

## Жизненный цикл

Новый релиз — `draft`, `published_at=null`. Администратор меняет версию, описание и файлы, явно назначает updater-пакеты и прикрепляет подписи. Оператор читает релизы и скачивает файлы через защищённый API.

**Проверить готовность** выполняет серверную проверку выбранного канала: активность приложения, состояние релиза, наличие файлов, размер и SHA-256, однозначность target/format и updater-пакетов. SemVer нормализуется и проверяется при создании/изменении; из SQLite релиз также читается через SemVer parser. Результат `ready`, `warnings` или `errors` содержит конкретные сообщения и UUID проблемного файла. Не задан список обязательных платформ: сервис универсален и не придумывает, какие платформы обязан выпускать продукт.

У updater-пакета без подписи предупреждение: его можно распространять как обычный файл, однако Tauri его не выберет. Несколько updater-пакетов на одну платформу — блокирующая неоднозначность, даже если это EXE и MSI. Исправьте роль лишнего файла на installer. Один target/format по-прежнему уникален.

**Опубликовать** открывает подтверждение с предлагаемой версией, текущей версией канала, числом файлов и результатом проверки. Сервер заново проверяет файлы; результат предварительной проверки не является разрешением на публикацию. Проверка читает порциями 64 КиБ через ArtifactStorage, с существующим ограничением параллелизма. Длительное хеширование не удерживает write-транзакцию SQLite.

После проверки короткая `BEGIN IMMEDIATE` повторно проверяет живую сессию/admin, активность приложения, ревизии релиза и канала и точное совпадение метаданных/состава файлов с проверенным snapshot. Затем атомарно устанавливает `published` и единственный `published_at`, добавляет membership, меняет current и записывает историю. Конфликт возвращает 409: обновите данные и подтвердите действие повторно. Счётчики ревизий обнаруживают также несколько изменений в одну секунду и переключение A → B → A. Загрузка, начатая до публикации, не сможет завершить INSERT после неё.

Опубликованный релиз нельзя редактировать, удалять, дополнять файлами или менять подписи/роли. Ограничения действуют в сервисах и SQLite triggers. Снятие с current не возвращает draft. Повтор завершённого запроса для той же текущей версии не меняет timestamps, revision или историю. Повреждённые файлы требуют восстановления из согласованного backup; обхода неизменяемости через панель нет.

## Каналы и откат

У приложения автоматически появляются `stable` и `beta`, включая приложения до этапа 5. Это записи с уникальным именем внутри приложения, а не enum в схеме: в будущем можно добавить другие каналы отдельным сценарием. API управления произвольными каналами сейчас нет.

Канал существует пустым. Current задаётся явно. Версия `1.4.0` может сначала попасть в beta, затем — в stable без копирования файлов и без изменения первого `published_at`. Prerelease, включая `-alpha`, `-beta` и `-rc`, запрещён в stable; обход этого ограничения в интерфейсе/API не предусмотрен. Суффикс версии не назначает канал автоматически.

В **Каналы обновлений → Переключить версию** выберите опубликованный релиз. Поиск и пагинация охватывают опубликованные версии приложения. После сравнения старой и новой версий подтвердите действие. Сервер снова проверит целостность, совместимость и revision. Так же можно впервые назначить в другой канал уже опубликованный релиз. Membership предыдущих версий сохраняется.

История неизменяема: `release_published` для первой публикации, `channel_promoted` для назначения опубликованной версии, `channel_rolled_back` для переключения на меньший SemVer. Build metadata не меняет приоритет. Каждая запись хранит приложение, канал, релиз, previous/new release, пользователя и время. Нажмите **История**; API поддерживает курсор `before`.

**Откат канала не равен downgrade клиента.** Он меняет версию, предлагаемую сервером. Уже установленный Tauri-клиент по умолчанию не установит меньшую или равную версию. Принудительное обновление, отключение сравнения и автоматический downgrade не реализованы.

## Универсальный манифест

Публичные URL:

- `GET /{slug}/manifest.json` — stable.
- `GET /{slug}/manifest.json?channel=beta` — выбранный канал.
- Необязательный `limit=1..100`, по умолчанию 20.

Короткий URL сохраняется как постоянный контракт. В будущем дополнительный версионированный адрес подключается под `/api/v1`, используя тот же ManifestGeneration; сейчас такой alias не зарегистрирован.

Документ `application/json` строится из согласованного read snapshot SQLite одним сервисом для public и admin preview. Независимых JSON-файлов нет. `schema_version=1`.

| Поле | Семантика |
| --- | --- |
| schema_version | Версия схемы документа, сейчас 1 |
| app / channel | Постоянный slug приложения / имя канала |
| latest | Версия явно назначенного current; может быть меньше другой версии в истории |
| releases | Только опубликованные members канала; current первым, затем остальные по убыванию SemVer, равенства разрешаются UUID |
| releases[].version | Нормализованный SemVer с build metadata |
| published_at | Первая публикация, UTC RFC 3339 с суффиксом Z |
| notes | Release notes |
| artifacts[] | id, target, format, size_bytes, sha256 |
| artifacts[].download_url | Рабочая постоянная ссылка UUID для active/public; private preview опускает поле |

Current всегда входит в limit, в том числе после отката при `limit=1`. Build metadata сохраняется, но не участвует в сравнении приоритета; существующая уникальность версии без build metadata сохранена. Сортировки строк для выбора current нет.

Каждый возвращаемый файл проверяется через ArtifactStorage по ключу/типу/размеру. Полное SHA-256 выполняется при хранении/публикации и явном verify, без повторного чтения гигабайтов на публичном запросе. История ограничена SQL LIMIT/OFFSET; current читается по указателю и включается первым.

`ETag` — слабый SHA-256 сериализованного документа, одинаковый для сжатого и несжатого представления. `If-None-Match` (включая список и `*`) даёт 304 без тела. Перед этим всегда проверяются публичность, активность и целостность; после скрытия приложения старый ETag не раскрывает его. `Cache-Control: public, no-cache` требует перепроверки.

Публичный запрос без cookie: 404 для private/archived, неизвестного slug и пустого канала. Неверный query/канал — 400. Черновики, signatures, storage keys и административные download URL в документ не входят. Admin preview private/archived доступен администратору с сессией; API preview — no-store.

Проверка после реальной публикации:

```sh
curl -i 'http://127.0.0.1:8080/your-slug/manifest.json?channel=stable&limit=20'
# Повторите с полученным значением ETag:
curl -i -H 'If-None-Match: W/"полученный-хеш"' \
  'http://127.0.0.1:8080/your-slug/manifest.json?channel=stable&limit=20'
```

В панели **Манифесты** доступны форматированный JSON, копирование JSON и публичного URL. Для private/archived копирование публичного URL выключено. Vite проксирует только `/api`: короткий URL проверяйте на порту Rust или в production.

## Tauri Updater v2

Адаптер следует [официальной документации Tauri v2](https://v2.tauri.app/plugin/updater/). Предпочтителен динамический протокол: SemVer клиента сравнивается с current выбранного канала, затем выбирается ровно один совместимый updater. Это те же публикации и файлы, что в универсальном манифесте.

Артефакты до этапа 5 получают `distribution_role=installer`. Расширение само по себе не включает updater. В черновике выберите **Tauri updater** только для пакета, созданного системой сборки с `bundle.createUpdaterArtifacts=true`:

| Внутренний target | Target Tauri | Поддерживаемый пакет v2 |
| --- | --- | --- |
| windows-x86_64 / windows-aarch64 | тот же OS-ARCH | EXE (NSIS) или MSI, явно назначенный updater |
| linux-x86_64 / linux-aarch64 | тот же OS-ARCH | AppImage |
| darwin-x86_64 / darwin-aarch64 | тот же OS-ARCH | app.tar.gz |

Вход preview также принимает aliases `macos`, `x64`, `arm64`, нормализуя их в `darwin`, `x86_64`, `aarch64`. Адаптер допускает стандартные Tauri `i686`/`armv7`, но загрузка этих платформ пока не входит в каталог TARGETS. ZIP v1Compatible, DMG, DEB, RPM, произвольный EXE без явного назначения не считаются updater-пакетами. Сервис проверяет соответствие метаданных; он не запускает/не распаковывает исполняемые файлы и не может удостоверить NSIS по одному расширению. За правильный сборочный пакет отвечает администратор/система сборки.

Рядом с пакетом Tauri создаёт `.sig`. Передайте его содержимое как отдельную подпись к UUID файла (до 16 КиБ). В панели виден факт наличия, доступны замена/удаление до публикации. Сервер проверяет структуру base64-encoded minisign-документа и размеры signature packets; это не криптографическая проверка пары пакет/подпись, поскольку сервер не хранит public key приложения. Финальную криптографическую проверку выполняет клиент с закреплённым публичным ключом. SHA-256 не заменяет подпись.

**Приватные ключи не передавайте серверу.** Их создание, хранение и подписание остаются в системе сборки. API принимает структуру `.sig`, отвергает key-файлы, пути и URL.

В **Манифесты → Tauri Updater preview** задайте канал, платформу и текущую версию клиента. Причины: empty_channel, application_not_public, version_not_newer, updater_package_missing, signature_missing, ambiguous_package, artifact_corrupted или update_available. При успехе state=available, public_downloads_available=true, response содержит реальный Tauri JSON. Preview возвращает 200 с диагностикой, неверный SemVer/target — 422.

Публичный endpoint `/api/v1/updates/tauri/{slug}/{channel}/{target}/{arch}/{currentVersion}` возвращает 200 с реальным URL и .sig либо 204 без тела. Downgrade не предлагается. Абсолютные ссылки используют текущий HTTPS-домен или явный download.public_base_url. Инструкция клиента/сборки: [Tauri](integrations/tauri.md).

## Примеры для продуктов

Это сценарии использования, без seed-записей или специальных правил в коде:

- **VideoLov:** создать приложение с выбранным постоянным slug, загрузить реальный Windows updater `1.4.0` и соответствующую `.sig`. Опубликовать в beta, проверить манифест/preview; после тестирования назначить тот же UUID релиза в stable. При проблеме вернуть current stable на предыдущий опубликованный релиз. Уже установленные клиенты автоматически не откатятся.
- **Factum:** опубликовать обычный дистрибутив в stable с ролью installer. Универсальный манифест содержит достоверные размер/хеш/платформу; Tauri preview объясняет отсутствие updater-пакета. Для внутреннего приложения оставить private: публичный манифест возвращает 404, административный preview доступен.

## Публичное распространение — этап 6

В разделе приложения **Распространение** установите installer по умолчанию, копируйте URL и проверяйте манифест/HEAD файлов. Публикация предупреждает, если селектор отсутствует в новом релизе. Опубликованный файл имеет постоянный URL, /latest разрешает current и перенаправляет 307. После rollback сохранённые ссылки работают, автоматического downgrade нет. Полный контракт: [публичное распространение](public-distribution.md); Nginx: [конфигурация](../deploy/nginx/README.md).

Вне этапа остаются статистика, CI/CD API-токены, private updates, принудительный downgrade, delta, S3/CDN и удаление старых релизов.
